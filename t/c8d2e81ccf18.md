## Пристрій / модель
| Параметр | Значення |
|----------|----------|
| **Бренд** | Nomi |
| **Модель** | C101034 Ultra4 LTE (планшет) |
| **Версія плати** | V01 (основна) – у темі згадується також V02, яка **не підходить** для даного пристрою |
| **Прошивка (з бекапу)** | `Nomi_C101034_V02_20181009` (Patch Level O11019, Android 8.1.0) |
| **Бажана прошивка** | `Nomi_C101034_V01_2018914_GO` (для V01) |
| **Програмне забезпечення для прошивки** | SP Flash Tool 5.22 (MediaTek) |

## Симптом / несправність
| № | Опис |
|---|------|
| 1 | Після прошивки **внутрішня флеш‑пам’ять** відображається як **4 ГБ** замість заявлених **16 ГБ**. |
| 2 | **Кнопки навігації** (панель) не реагують, працюють лише при перевертанні планшету «верх‑ногами». |
| 3 | При деяких спробах (формат + завантаження) **пристрій не завантажується** – зависає на логотипі (boot‑loop). |
| 4 | У Recovery можна зайти, проте **reset** не працює, бо `userdata`‑розділ не створюється. |
| 5 | Після успішного завантаження (без формату) сенсор працює, але навігація залишилась «мертвою». |

## Діагностика
| Дія | Результат / вимірювання |
|-----|--------------------------|
| Злив дампа (бекап) з нової (не‑модифікованої) плати | Показано в першому пості – дані прошивки без проблем. |
| Flash через **SP Flash Tool** з опцією **Format All + Download** | Після цього пристрій «запав» (boot‑loop) і бачить лише 4 ГБ. |
| Flash без форматування (тільки **Download**) | Пристрій завантажується, але все ще бачить 4 ГБ і має проблеми з навігацією. |
| Перевірка версії плати (фото плати) | Виявлено, що плата **V01**, а використана прошивка – **V02**. |
| Аналіз `scatter`‑файлу | Розмір розділу **SYS26** (який відповідає за `userdata`) встановлений як `0x80000000` (≈2 ГБ) → система бачить лише 4 ГБ (2 ГБ + інші системні). |
| Зміна `partition_size` у `scatter`‑файлі | Після заміни `0x80000000` → `0x2A0000000` (≈10,5 ГБ) система бачить **весь 16 ГБ**. |
| Перевірка навігаційної панелі після зміни `scatter` | Панель все ще не реагує – підозра на несумісність прошивки (V02 vs V01). |

> **⚠️ потребує перевірки** – у темі немає конкретних кодів помилок, лише опис симптомів.

## Деталі та аналоги
| Елемент | Опис |
|---------|------|
| **Firmware backup** (з першого посту) | `Patch Level: O11019`<br>`Display ID: Nomi_C101034_V02_20181009`<br>`Android 8.1.0` |
| **Неправильна ревізія** | `V02` – підходить лише для плат **V02**; у користувача **V01**. |
| **Потрібна прошивка** | `Nomi_C101034_V01_2018914_GO` (запропоновано у пості 10). |
| **Програматор** | SP Flash Tool 5.22 (з драйверами MediaTek). Фізичний програматор (наприклад, **Infinity‑Box**) не використовується, але згадується як можливий варіант. |
| **Scatter‑файл** | Файл, що описує розмітку флеш‑пам’яті MediaTek. Потрібно редагувати розмір розділу `SYS26`. |
| **Параметр `SYS26`** | `partition_index: SYS26`<br>`partition_size: 0x80000000` → **змінити** на `0x2A0000000`. |
| **Аналоги** | Подібні проблеми з розміром пам’яті у інших MediaTek‑плат (наприклад, планшети **Allwinner**, **Rockchip**) вирішуються аналогічним редагуванням `scatter`. |

## Покроковий ремонт
1. **Створити резервну копію** (якщо можливо) за допомогою фізичного програматора або `adb pull` у режимі Recovery.  
2. **Завантажити правильну прошивку** для вашої ревізії плати: `Nomi_C101034_V01_2018914_GO`.  
3. **Розпакувати прошивку** і знайти файл `scatter.txt`.  
4. **Відкрити `scatter.txt` у текстовому редакторі** (наприклад, Notepad++).  
5. **Знайти рядок**:  
   ```
   partition_index: SYS26
   partition_size: 0x80000000
   ```  
6. **Замінити** `0x80000000` на `0x2A0000000` (значення, що відповідає 16 ГБ).  
7. **Зберегти файл** і переконатися, що кодування – UTF‑8 без BOM.  
8. **Запустити SP Flash Tool 5.22**:  
   - Встановити драйвери MediaTek (VCOM).  
   - Увімкнути **Download Only** (не ставити галочку *Format All*).  
   - Додати `scatter.txt`.  
   - Підключити планшет у режимі **Download Mode** (вимкнути, потім утримувати кнопку **Volume‑Down + Power**).  
   - Натиснути **Download** і дочекатися успішного завершення.  
9. **Перезавантажити пристрій** – система повинна бачити **16 ГБ**.  
10. **Перевірити навігаційну панель**. Якщо кнопки все ще не працюють, спробувати:  
    - Завантажити прошивку **V01** (а не V02).  
    - Якщо проблема залишається – можливо, потрібен **драйвер/прошивка для панелі** або фізичний програматор для перепрошивки контролера панелі.

## Результат
| Пункт | Висновок |
|-------|----------|
| **Об’єм пам’яті** | Після зміни `scatter`‑файлу система бачить весь 16 ГБ. |
| **Boot** | При використанні лише **Download** (без форматування) пристрій завантажується. |
| **Навігаційна панель** | Проблема **не вирішена** – ймовірно, через використання прошивки V02 на платі V01. |
| **Загальний підсумок** | Основна проблема з розміром пам’яті вирішена; залишилась проблема з панеллю навігації, яку треба вирішувати окремо (правильна прошивка V01 або спеціальна прошивка контролера). |

## Застереження / нюанси
- **Версія плати має відповідати прошивці.** Використання V02‑прошивки на V01‑платі призводить до помилок розмітки флеш‑пам’яті та можливих проблем з апаратними модулями (наприклад, панель навігації).  
- **Не використовуйте “Format All”**, якщо не плануєте переписувати таблицю розділів вручну – це може знищити інформацію про розмір флеш‑пам’яті.  
- **Редагування `scatter.txt`** – помилка у HEX‑значенні може зробити пристрій не завантажуваним. Завжди робіть копію оригінального файлу.  
- **Драйвери MediaTek** (VCOM) повинні бути встановлені коректно; без них SP Flash Tool не розпізнає пристрій у режимі Download.  
- Якщо після всіх маніпуляцій **boot‑loop** або **Recovery** не дозволяє створити `userdata`, можливо, таблиця розділів пошкоджена – у цьому випадку потрібен **фізичний програматор** (Infinity‑Box, MTK‑Downloader) для перепрошивки контролера eMMC.  
- **Навігаційна панель** може вимагати окремого драйвера або прошивки (наприклад, `touch_key.bin`). Якщо після встановлення правильної прошивки V01 панель не працює, варто перевірити:  
  1. Підключення шлейфу (можливі фізичні пошкодження).  
  2. Наявність файлу `keylayout` у `/system/usr/keylayout/`.  
  3. Оновлення `kernel`‑модуля, що відповідає за кнопку.

**Підсумок:**  
Технічна частина теми містить достатньо інформації, щоб відтворити успішне відновлення повного об’єму пам’яті (16 ГБ) шляхом корекції `scatter`‑файлу та використання правильної прошивки для V01‑плати. Проблема з навігаційною панеллю залишилась відкритою і потребує додаткових дій (правильна прошивка V01, можливо, окремий драйвер або фізичний програматор).
