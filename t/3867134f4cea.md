**Пристрій / модель:**
*   **Anengji** (згадано автором теми як власний прилад, піднятий ним).
*   **Oukitel P2001E Plus** (та варіація PRO) — згадано у контексті пошуку прошивок та дампу.
*   **Oukitel P2000 PLUS** (плата керування `P2000PLUS-CTRL-V1.4`, стікери `P2001TT-DC / 930-11002-01`, ПЗ 103) — запит на допомогу в кінці теми.
*   **Клони/Одноплатники** з процесорами серії **TMS320F28xxx** (зокрема `TMS320F28034`, `TMS320F280025`).

**Симптом / несправність:**
*   «Мертвий» мікроконтролер (процесор) на платі інвертора або передньої панелі.
*   Пристрій не стартує, оновлення через офіційний утиліт (`Iaptool.exe`) неможливе, оскільки він не бачить пристрій без завантаженого заводського бутлоадера.

**Діагностика:**
*   Визначено тип процесора: `TMS320F28xxx` (серія TI C2000) або ARM GigaDevice (`GD32`).
*   Аналіз утиліти оновлення `Iaptool.exe`: виявлено, що вона використовує шифрування **AES-256** (режим CBC, padding PKCS#7, блок 128 біт).
*   Виявлено, що файл прошивки має розширення `*.udt`, який є зашифрованим HEX-файлом.
*   Визначено ключі для дешифрування (витягнуті з `Iaptool.exe`):
    *   Ключ: `Ng4aEcEzjwtjKzwhqmynOjrbjJSaZxHJ`
    *   IV (Initialization Vector): `wBVBT7aApgSI007x`
*   Встановлено, що перед AES-шифруванням файл кодується в **Base64**.

**Коди помилок:**
*   У темі не зазначено конкретних кодів помилок на дисплеї. Основна проблема — відсутність реакції пристрою на спроби оновлення через офіційний софт.

**Деталі та аналоги:**
*   **Процесори:** `TMS320F28034`, `TMS320F280025` (TI), `GD32` (GigaDevice).
*   **Інструменти для розшифровки:**
    *   Власний скрипт/інструмент для дешифрування `*.udt` у HEX.
    *   Програма **C2Prog** (для запису прошивки в процесори TI C2000).
*   **Спосіб запису:** Через порт RS232 (UART/SCI) без програматора, шляхом замикання на землю двох пінів JTAG роз'єму (піни 2 та 7) для активації режиму прошивки по SCI.
*   **Дампи:** Користувач `F.O.V` надав дамп інвертора для Oukitel P2001E Plus (процесор `F280025pnc`, вичитаний з прогорілої плати, де процесор не мав КЗ).

**Покроковий ремонт:**
1.  **Аналіз софту:** Розбір файлу `Iaptool.exe` для витягування ключів шифрування (AES-256) та алгоритму кодування (Base64 + AES CBC).
2.  **Дешифрування прошивки:** Використання знайдених ключів для розшифровки файлу `*.udt` у чистий HEX/OUT формат.
3.  **Підготовка апаратної частини:** Заміна згорілого процесора на новий (або донорський).
4.  **Активація режиму завантаження:** Фізичне замикання пінів 2 та 7 роз'єму JTAG на землю для входу в режим SCI-завантаження (Bootloader mode).
5.  **Прошивка:** Підключення до комп'ютера через RS232/USB-to-TTL та запис дешифрованої прошивки за допомогою програми **C2Prog**.
    *   *Примітка:* Автор теми спробував залити знайдену в мережі прошивку в форматі OUT, але це не спрацювало (можливий захист або несумісність).

**Результат:**
*   **Автор теми (Tonksai):** Успішно відновив інвертор бренду **Anengji**, замінивши процесор та залити дешифровану прошивку.
*   **Oukitel P2001E Plus:** Користувач `F.O.V` надав дамп з робочої плати, але зауважив, що коричневий варіант інвертора (також на 2001E PRO) ще не до кінця відновлений через можливі проблеми з прошивкою.
*   **Oukitel P2000 PLUS (GD32):** Запит користувача `Сергей Хатмулаевич` залишено без відповіді в межах теми; дешифрований файл `.udt` для цієї лінійки плати не був наданий.
*   **Загальний висновок:** Методика розшифровки та прошивки через SCI підтверджена на прикладі Anengji, але вимагає наявності саме дешифрованої прошивки для конкретної моделі плати.

**Застереження / нюанси:**
*   ⚠️ **Безпека даних:** Ключі шифрування та методи розбору `Iaptool.exe` опубліковані в темі, що може бути використано для модифікації прошивок.
*   ⚠️ **Сумнівні дані:** Автор теми зазначив, що писав під час обстрілів («під вибухи реактивних шахедів»), тому можливі помилки в описі або ключах (хоча ключі виглядають коректними для AES-256).
*   **Обмеження методу:** Офіційна утиліта `Iaptool` працює лише з процесорами, що мають завантажений заводський бутлоадер. Для «чистих» процесорів потрібен апаратний перехід у режим SCI (замикання пінів).
*   **Сумісність:** Прошивка від однієї моделі може не працювати на іншій, навіть з тим самим процесором (захист, кастомні ідентифікатори в бутлоадері).
*   **Процесори GD32:** Методика описана для TI C2000 (`TMS320...`). Для ARM GigaDevice (`GD32`) потрібна інша методика та програмне забезпечення, яке в темі не розкрито.
